# คู่มือติดตั้งและทดสอบ

ระบบบริหารจัดเก็บเงินบำรุงการศึกษา โรงเรียนวัดเสาหิน จังหวัดเชียงใหม่

> คู่มือนี้จะเพิ่มขั้นตอนเมื่อจบแต่ละระยะ ปัจจุบันครอบคลุม **ระยะที่ 1: โครงสร้างระบบและฐานข้อมูล**
> ในระยะนี้ **ยังไม่ต้อง Deploy เว็บแอป** เพราะยังไม่มีระบบ Login (มาในระยะที่ 2)

---

## ระยะที่ 1: ติดตั้งโครงสร้างฐานข้อมูล

### สิ่งที่ต้องเตรียม

1. **บัญชี Google ที่จะเป็นเจ้าของระบบ**
   - แนะนำบัญชีกลางของโรงเรียน ไม่ใช่บัญชีส่วนตัวของครู
   - เปิด 2-Step Verification (การยืนยันแบบ 2 ขั้นตอน)
2. **ไฟล์ Google Sheets ที่สร้างไว้** โดยเปิดด้วยบัญชีเจ้าของระบบ
3. **ปิดบัญชี Google อื่นในเบราว์เซอร์** หรือใช้หน้าต่างที่ login บัญชีเจ้าของเพียงบัญชีเดียว
   ถ้า login หลายบัญชีพร้อมกัน Google อาจรันสคริปต์ด้วยบัญชีอื่นและเกิดข้อผิดพลาดเรื่องสิทธิ์

### ขั้นตอนที่ 1: เปิด Apps Script ที่ผูกกับ Google Sheets

1. เปิดไฟล์ Google Sheets ที่จะใช้เป็นฐานข้อมูล
2. เมนู **ส่วนขยาย (Extensions) → Apps Script**
3. คลิกชื่อโปรเจกต์มุมซ้ายบน แล้วตั้งชื่อ เช่น `ระบบเงินบำรุงการศึกษา`

### ขั้นตอนที่ 2: ใส่ไฟล์ appsscript.json

1. คลิก **⚙️ การตั้งค่าโปรเจกต์ (Project Settings)** ที่แถบซ้าย
2. ติ๊ก **แสดงไฟล์ Manifest "appsscript.json" ในเครื่องมือแก้ไข** (Show "appsscript.json" manifest file in editor)
3. กลับไปที่ **เครื่องมือแก้ไข (Editor)** แล้วเปิดไฟล์ `appsscript.json`
4. ลบเนื้อหาเดิมทั้งหมด แล้ววางเนื้อหาจากไฟล์ [`src/appsscript.json`](../src/appsscript.json)
5. ตรวจว่ามีบรรทัด `"timeZone": "Asia/Bangkok"`

### ขั้นตอนที่ 3: สร้างไฟล์สคริปต์ 7 ไฟล์

| ชื่อไฟล์ในเครื่องมือแก้ไข | คัดลอกเนื้อหาจาก | หน้าที่ |
|---|---|---|
| `Code` | [`src/Code.js`](../src/Code.js) | จุดเข้าของเว็บแอป (วางทับไฟล์ `Code.gs` เดิมที่มี `myFunction`) |
| `Config` | [`src/Config.js`](../src/Config.js) | ค่าคงที่และโครงสร้างชีตทั้งหมด |
| `Shared` | [`src/Shared.js`](../src/Shared.js) | จัดรูปแบบเงิน วันที่ พ.ศ. และจำนวนเงินเป็นตัวอักษร |
| `Utils` | [`src/Utils.js`](../src/Utils.js) | ฟังก์ชันช่วยฝั่ง Server |
| `Db` | [`src/Db.js`](../src/Db.js) | อ่านและเขียนชีต พร้อม lock และกันข้อมูลซ้ำ |
| `Audit` | [`src/Audit.js`](../src/Audit.js) | ประวัติการใช้งานแบบลูกโซ่ hash |
| `Setup` | [`src/Setup.js`](../src/Setup.js) | `SetupDatabase()` และเมนูใน Google Sheets |

วิธีสร้างแต่ละไฟล์:

1. คลิกเครื่องหมาย **+** ข้างคำว่า **ไฟล์ (Files)** → **สคริปต์ (Script)**
2. พิมพ์ชื่อตามตาราง โดยไม่ต้องพิมพ์ `.gs`
3. ลบโค้ดตัวอย่างในไฟล์ใหม่ แล้ววางเนื้อหาทั้งหมดจากไฟล์ใน repo
4. กด **Ctrl+S** (Mac: **⌘+S**) เพื่อบันทึก

ลำดับของไฟล์ในแถบซ้ายไม่มีผลต่อการทำงาน

### ขั้นตอนที่ 4: ติดตั้งฐานข้อมูล

1. กลับไปที่แท็บ Google Sheets แล้วกด **F5** เพื่อรีเฟรช
2. รอประมาณ 5–10 วินาที จนเมนู **ระบบเงินบำรุงการศึกษา** ปรากฏข้างเมนูความช่วยเหลือ
3. เลือก **ระบบเงินบำรุงการศึกษา → 1) ติดตั้ง / ตรวจสอบโครงสร้างฐานข้อมูล**
4. ครั้งแรก Google จะขอให้อนุญาตสิทธิ์:
   1. กด **ดำเนินการต่อ (Continue)** แล้วเลือกบัญชีเจ้าของระบบ
   2. ถ้าเห็นข้อความว่า Google ยังไม่ได้ยืนยันแอปนี้ (Google hasn't verified this app) ให้กด **ขั้นสูง (Advanced)** แล้วกดลิงก์ไปยังชื่อโปรเจกต์ ข้อความนี้ปรากฏกับสคริปต์ที่เขียนเองทุกตัว
   3. ตรวจรายการสิทธิ์ แล้วกด **อนุญาต (Allow)**

   ระบบขอสิทธิ์ 3 อย่าง (ดูได้ที่ `oauthScopes` ใน `appsscript.json`):

   | สิทธิ์ | ใช้ทำอะไร |
   |---|---|
   | Google Sheets | อ่านและเขียนไฟล์ฐานข้อมูล |
   | แสดงเมนูและกล่องข้อความใน Google Sheets | เมนูติดตั้งและการแจ้งผล |
   | ดูอีเมลของบัญชี | ตรวจว่าผู้สั่งติดตั้งเป็นเจ้าของระบบ |

5. หลังอนุญาต ถ้ายังไม่เห็นกล่องยืนยัน ให้เลือกเมนูเดิมอีกครั้ง
6. กล่องยืนยันแจ้งว่าจะสร้างเฉพาะสิ่งที่ยังไม่มี กด **ใช่ (Yes)**
7. รอประมาณ 10–30 วินาที ระบบจะแสดง **ผลการติดตั้งฐานข้อมูล**

### ขั้นตอนที่ 5: ตรวจผลการติดตั้ง

ตรวจทีละข้อ:

- [ ] กล่องผลการติดตั้งแจ้ง **สร้างชีตใหม่ 15 ชีต** และ **เพิ่มค่าตั้งค่าเริ่มต้น 22 รายการ**
- [ ] มีแท็บชีตครบ 15 ชีต:
  `Users`, `SchoolSettings`, `AcademicYears`, `Students`, `Enrollments`, `FeeSettings`, `FeeAssessments`, `FeeAdjustments`, `Payments`, `PaymentAllocations`, `ReceiptBooks`, `ReceiptEntries`, `ReceiptCancellations`, `ApprovalRequests`, `AuditLogs`
- [ ] แถวแรกของทุกชีตเป็นหัวตารางพื้นสีกรมท่า ตัวอักษรสีขาว และถูกตรึงไว้
- [ ] ชี้เมาส์ที่หัวคอลัมน์ใดก็ได้ จะเห็นคำอธิบายภาษาไทย
- [ ] ชีต `SchoolSettings` มี 22 แถว และค่า `CURRENT_ACADEMIC_YEAR` เป็น `2569` (คำนวณจากวันที่ติดตั้ง)
- [ ] ชีต `AuditLogs` มี 23 แถว:
  - `CREATE` 22 แถวจากค่าตั้งค่า
  - `SETUP` 1 แถว
  - ทุกแถวมีค่าในคอลัมน์ `Hash`
- [ ] ลองพิมพ์ในเซลล์ว่างของชีตใดก็ได้ Google จะเตือนว่าเป็นช่วงที่ได้รับการป้องกัน ให้กด **ยกเลิก (Cancel)**
- [ ] ใน Apps Script ที่ **⚙️ การตั้งค่าโปรเจกต์ → คุณสมบัติของสคริปต์ (Script Properties)** มี 4 ค่า:
  `DB_SPREADSHEET_ID`, `AUTH_MODE` (ค่า `PASSWORD`), `PASSWORD_PEPPER`, `AUDIT_HEAD`

> ⚠️ **ห้ามแก้ ลบ หรือเปิดเผยค่า `PASSWORD_PEPPER`**
> ระยะที่ 2 ใช้ค่านี้แฮชรหัสผ่าน ถ้าค่าเปลี่ยน รหัสผ่านของทุกคนจะใช้ไม่ได้

### ขั้นตอนที่ 6: ทดสอบว่ารันซ้ำได้โดยไม่ทำลายข้อมูล

1. เลือกเมนู **1) ติดตั้ง / ตรวจสอบโครงสร้างฐานข้อมูล** อีกครั้ง แล้วกด **ใช่**
2. ผลต้องเป็น **โครงสร้างครบถ้วน ไม่มีการเปลี่ยนแปลง**
3. ชีต `SchoolSettings` ยังมี 22 แถว (ไม่มีค่าซ้ำ)
4. ชีต `AuditLogs` เพิ่มขึ้น 1 แถว เป็น `SETUP` ที่มีหมายเหตุ "ไม่มีการเปลี่ยนแปลง"

### ขั้นตอนที่ 7: ทดสอบการตรวจจับการแก้ไขประวัติ

> ทำขั้นตอนนี้ได้เฉพาะตอนติดตั้ง ก่อนเริ่มใช้งานจริงเท่านั้น

1. เลือกเมนู **2) ตรวจสอบความถูกต้องของประวัติการใช้งาน**
   ผลต้องเป็น **ถูกต้อง: ประวัติการใช้งาน 24 รายการ ต่อเนื่องครบถ้วน**
2. ไปที่ชีต `AuditLogs` แล้วพิมพ์คำใดก็ได้ในคอลัมน์ `Note` ของแถวที่ 5 (ยอมรับคำเตือน)
3. เลือกเมนู **2)** อีกครั้ง ระบบต้องแจ้ง **พบปัญหา** ที่ **แถว 5: ข้อมูลในแถวนี้ถูกแก้ไขหลังบันทึก**
4. กด **Ctrl+Z** (เลิกทำ) เพื่อคืนค่าเดิม แล้วตรวจอีกครั้ง ผลต้องกลับมาเป็น **ถูกต้อง**

### ข้อห้ามหลังติดตั้ง

| ห้าม | เหตุผล |
|---|---|
| แชร์ไฟล์ Google Sheets หรือโปรเจกต์ Apps Script ให้ผู้อื่นแก้ไข | ผู้ใช้ทุกคนต้องเข้าผ่านเว็บแอปเท่านั้น ระบบจึงควบคุมสิทธิ์และบันทึกประวัติได้ |
| เปลี่ยนชื่อชีต หรือชื่อหัวคอลัมน์ | โค้ดอ้างอิงตามชื่อ |
| จัดเรียง (Sort) กรอง แล้วแก้ หรือลบแถวในชีต | ระบบออกแบบให้ข้อมูลไม่ถูกลบ (ถ้ามีการย้ายแถว ระบบจะหยุดการบันทึกเพื่อป้องกันข้อมูลผิดแถว) |
| แก้ข้อมูลในชีตด้วยมือ | การแก้ด้วยมือข้ามการตรวจสิทธิ์และไม่มีประวัติ ส่วนการแก้ AuditLogs จะถูกตรวจพบ |
| แก้หรือลบค่าใน Script Properties | ทำให้ระบบเปิดฐานข้อมูลหรือตรวจรหัสผ่านไม่ได้ |

เมื่อต้องเพิ่มคอลัมน์ในอนาคต:

1. แก้ไฟล์ `Config` (เพิ่มคอลัมน์ต่อท้ายรายการของชีตนั้น)
2. รันเมนู **1)** ระบบจะเพิ่มคอลัมน์ให้ โดยไม่ย้ายหรือแก้ข้อมูลเดิม

### ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
|---|---|
| ไม่เห็นเมนู | รีเฟรชหน้า Google Sheets และตรวจว่าบันทึกไฟล์ `Setup` แล้ว |
| "คำสั่งนี้ใช้ได้เฉพาะเจ้าของระบบ" | ต้องเปิดไฟล์ด้วยบัญชีเจ้าของ และปิดบัญชีอื่นในเบราว์เซอร์ |
| "ขณะนี้มีผู้ใช้อื่นกำลังบันทึกข้อมูล" | รอประมาณ 30 วินาทีแล้วลองใหม่ |
| "ชีต … มีข้อมูลแต่ไม่มีหัวตาราง" | ระบบหยุดเพื่อไม่ให้ข้อมูลเดิมเสียหาย ให้ตรวจชีตนั้นด้วยตนเอง (เช่น เปลี่ยนชื่อชีตเดิมเป็นชื่ออื่น) แล้วรันใหม่ |
| "ชีต … มีหัวคอลัมน์ … ซ้ำกัน" | ลบหัวคอลัมน์ที่ซ้ำให้เหลือคอลัมน์เดียว แล้วรันใหม่ |
| Error เรื่อง `DB_SPREADSHEET_ID` | ตรวจค่าใน Script Properties ถ้าเพิ่งติดตั้งครั้งแรก ให้ลบค่านี้แล้วรันเมนู 1) ใหม่ |
| เมนูทำงานแต่ไม่มีอะไรเกิดขึ้น | ดูข้อผิดพลาดที่ Apps Script → **การดำเนินการ (Executions)** |

## สำหรับผู้พัฒนา

### รันชุดทดสอบอัตโนมัติ (ไม่ต้องเชื่อมต่อ Google)

ต้องมี Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm test
```

ชุดทดสอบใน `tests/` รันโค้ดจริงใน `src/` กับ Google Sheets จำลอง (`tests/harness.js`)
ตัวจำลองเข้มงวดกว่าของจริงในจุดเสี่ยง:

- แปลงข้อความเป็นตัวเลขหรือวันที่อัตโนมัติ ถ้าเซลล์ไม่ได้ตั้งเป็น Plain text
- ตีความข้อความที่ขึ้นต้นด้วย `=` เป็นสูตร
- error เมื่ออ้างช่วงเซลล์เกินขนาดชีต

### อัปโหลดด้วย clasp (ไม่บังคับ)

ใช้แทนการคัดลอกและวางทีละไฟล์

1. ติดตั้งและเข้าสู่ระบบ

   ```bash
   npm install -g @google/clasp
   ```

   ```bash
   clasp login
   ```

2. คัดลอก `.clasp.json.example` เป็น `.clasp.json` แล้วใส่ Script ID
   (ดูได้ที่ Apps Script → ⚙️ การตั้งค่าโปรเจกต์ → รหัสสคริปต์)
3. อัปโหลดไฟล์ทั้งหมดใน `src/` (clasp แปลง `.js` เป็น `.gs` ให้อัตโนมัติ)

   ```bash
   clasp push
   ```
