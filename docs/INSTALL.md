# คู่มือติดตั้งและทดสอบ

ระบบบริหารจัดเก็บเงินบำรุงการศึกษา โรงเรียนวัดเสาหิน จังหวัดเชียงใหม่

> ปัจจุบันครอบคลุมถึง **ระยะที่ 3: ระบบนักเรียน** (ข้อมูลนักเรียน นำเข้าจาก Excel/CSV เลื่อนชั้น)
> ทั้งระบบอยู่ในไฟล์เดียวคือ [`dist/Code.gs`](../dist/Code.gs) ทั้งการติดตั้งครั้งแรกและการอัปเดตใช้วิธีวางไฟล์เดียวเหมือนกัน

---

## เตรียมก่อนเริ่ม

1. **บัญชี Google ที่จะเป็นเจ้าของระบบ**
   - แนะนำบัญชีกลางของโรงเรียน ไม่ใช่บัญชีส่วนตัวของครู
   - เปิด 2-Step Verification
2. **ไฟล์ Google Sheets ที่สร้างไว้** เปิดด้วยบัญชีเจ้าของระบบ
3. **ใช้คอมพิวเตอร์** และให้เบราว์เซอร์ login บัญชี Google ไว้เพียงบัญชีเดียว
   - ถ้า login หลายบัญชี Google อาจรันสคริปต์ด้วยบัญชีอื่นแล้วเกิดข้อผิดพลาดเรื่องสิทธิ์
   - วิธีง่ายที่สุด: เปิด **หน้าต่างไม่ระบุตัวตน (Incognito)** ด้วย Ctrl+Shift+N แล้ว login เฉพาะบัญชีเจ้าของระบบ

## ติดตั้งครั้งแรก (6 ขั้นตอน)

### 1. เปิด Apps Script

ใน Google Sheets ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**

### 2. คัดลอกโค้ด

1. เปิดไฟล์ [`dist/Code.gs`](../dist/Code.gs) บน GitHub
2. กดปุ่ม **Copy raw file** (ไอคอนสี่เหลี่ยมซ้อน มุมขวาบนของกล่องโค้ด)

### 3. วางโค้ด

1. ในหน้า Apps Script คลิกในไฟล์ `Code.gs`
2. กด **Ctrl+A** แล้ว **Ctrl+V** (วางทับทั้งหมด)
3. กด **Ctrl+S** (บันทึก)

บน Mac ใช้ ⌘ แทน Ctrl

### 4. ติดตั้งฐานข้อมูล

1. ช่องรายชื่อฟังก์ชันด้านบนต้องเป็น **`SetupDatabase`** → กด **▶ เรียกใช้ (Run)**
2. ครั้งแรก Google จะขออนุญาต:
   1. กด **ตรวจสอบสิทธิ์ (Review permissions)** → เลือกบัญชีเจ้าของระบบ
   2. ถ้าเห็นข้อความว่า Google ยังไม่ได้ยืนยันแอปนี้ ให้กด **ขั้นสูง (Advanced)** → **ไปที่ … (ไม่ปลอดภัย)**
      ข้อความนี้ปรากฏกับสคริปต์ที่โรงเรียนเขียนเองทุกตัว
   3. กด **อนุญาต (Allow)**
3. ถ้ารอบแรกหยุดไปเพราะขออนุญาต ให้กด **▶ เรียกใช้** อีกครั้ง
4. ช่อง **บันทึกการดำเนินการ (Execution log)** ด้านล่างต้องแสดง **สร้างชีตใหม่ 15 ชีต** และ **สร้างปีการศึกษาเริ่มต้น 2569**

### 5. สร้างผู้ดูแลระบบคนแรก

ทำครั้งเดียว โดยบัญชีเจ้าของไฟล์เท่านั้น (บัญชีผู้ใช้อื่นสร้างในหน้าเว็บ ดูข้อ 6)

1. กลับไปที่ **Google Sheets** (ไม่ใช่หน้าเว็บแอป) แล้วกด **F5** (รีเฟรช)
2. รอ 5–10 วินาที จนเมนู **ระบบเงินบำรุงการศึกษา** ปรากฏที่แถบเมนูด้านบน (ต่อจากเมนู "ความช่วยเหลือ")
3. เลือกเมนู **ระบบเงินบำรุงการศึกษา → 3) สร้างหรือรีเซ็ตบัญชีผู้ดูแลระบบ**
   - ถ้า Google ขออนุญาตอีกครั้ง ให้อนุญาตแบบเดียวกับขั้นตอนที่ 4 แล้วเลือกเมนูนี้ซ้ำ
4. กรอกในหน้าต่างที่ปรากฏ:

   | ช่อง | กรอก |
   |---|---|
   | ชื่อผู้ใช้ | ภาษาอังกฤษตัวพิมพ์เล็ก เช่น `admin` |
   | ชื่อ-นามสกุล | ชื่อของผู้ดูแลระบบ |
   | อีเมล | เว้นว่างได้ |
   | รหัสผ่าน และ ยืนยันรหัสผ่าน | อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข และต้องไม่มีชื่อผู้ใช้อยู่ในรหัสผ่าน (ชื่อผู้ใช้ `admin` ใช้ `Admin2569` ไม่ได้ แต่ใช้ `Saohin2569` ได้) |
   | ให้เปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก | ติ๊กไว้ถ้าสร้างให้คนอื่น / เอาติ๊กออกได้ถ้าสร้างให้ตัวเอง |

5. กด **บันทึก** → ต้องขึ้นข้อความ **สร้างบัญชีผู้ดูแลระบบ "admin" เรียบร้อยแล้ว**

ถ้าไม่เห็นเมนู หรือกดบันทึกแล้วขึ้นว่าเชื่อมต่อไม่สำเร็จ ดูตาราง [ปัญหาที่พบบ่อย](#ปัญหาที่พบบ่อย)

### 6. เผยแพร่เว็บแอป

1. ในหน้า Apps Script กดปุ่ม **Deploy (ทำให้ใช้งานได้)** มุมขวาบน → **New deployment (การทำให้ใช้งานได้รายการใหม่)**
2. กดรูปเฟือง ⚙ ข้าง **Select type** → เลือก **Web app (เว็บแอป)**
3. ตั้งค่า:

   | ช่อง | ค่าที่ต้องเลือก | เหตุผล |
   |---|---|---|
   | Description | `ระยะที่ 3` | ชื่อเวอร์ชัน |
   | Execute as | **Me (อีเมลเจ้าของระบบ)** | ผู้ใช้ไม่ต้องมีสิทธิ์ในไฟล์ Google Sheets จึงแก้ข้อมูลข้ามระบบไม่ได้ |
   | Who has access | **Anyone with Google account** | ต้องลงชื่อเข้าใช้ Google ก่อนจึงเห็นหน้าเข้าสู่ระบบ |

   ⚠️ **ห้ามเลือก Execute as = User accessing the web app** เพราะต้องแชร์ไฟล์ให้ทุกคน และทุกคนจะแก้ตัวเลขในชีตได้โดยตรง

4. กด **Deploy** (ถ้าขออนุญาต ให้อนุญาต)
5. คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) ลิงก์นี้คือที่อยู่ของระบบ ใช้ส่งให้ผู้ใช้
6. เปิดลิงก์ → เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ → ทำตามรายการ **เริ่มต้นใช้งาน** ในหน้าหลัก:
   1. กรอกข้อมูลโรงเรียนและชื่อผู้ลงนาม
   2. เพิ่มผู้ใช้เจ้าหน้าที่การเงินและผู้อำนวยการ
   3. ตรวจปีการศึกษาปัจจุบัน

> ผู้ใช้ทุกคนต้องลงชื่อเข้าใช้ Google (บัญชีใดก็ได้) ในเบราว์เซอร์ก่อน แล้วจึงเข้าสู่ระบบของโรงเรียนด้วยชื่อผู้ใช้และรหัสผ่านที่ผู้ดูแลระบบสร้างให้

## อัปเดตเมื่อมีเวอร์ชันใหม่

1. ทำ **ขั้นตอนที่ 2–4** ของการติดตั้ง (คัดลอก → วางทับทั้งหมด → บันทึก → Run `SetupDatabase`)
2. **Deploy → Manage deployments (จัดการการทำให้ใช้งานได้)** → เลือกรายการเดิม → กดรูปดินสอ ✏️
3. ช่อง **Version** เลือก **New version (เวอร์ชันใหม่)** → กด **Deploy**

- ลิงก์ `/exec` เดิมใช้ได้ต่อ ข้อมูลเดิมไม่หาย
- ถ้าข้ามข้อ 2–3 เว็บแอปจะยังเป็นเวอร์ชันเก่า
- **ถ้าติดตั้งระยะที่ 1 ไว้แล้ว:** อัปเดตตามข้อ 1 แล้วทำขั้นตอนที่ 5–6 ของการติดตั้งครั้งแรก
- ตรวจว่าอัปเดตสำเร็จ: ด้านล่างหน้าเข้าสู่ระบบแสดง **เวอร์ชัน 0.3.0** และหน้าหลักแสดง **ระยะที่ 3 จาก 8**

### หลังอัปเดตเป็นระยะที่ 3

1. ผู้ดูแลระบบเปิดเมนู **ตั้งค่าโรงเรียน** → ตรวจช่อง **ระดับชั้นที่เปิดสอน** ให้ตรงกับโรงเรียนจริง เรียงจากชั้นต่ำไปสูง คั่นด้วยจุลภาค
   - ค่าเริ่มต้นคือ `อ.1,อ.2,อ.3,ป.1,ป.2,ป.3,ป.4,ป.5,ป.6`
   - ถ้าโรงเรียนไม่มี อ.1 ให้ลบออก เช่น `อ.2,อ.3,ป.1,ป.2,ป.3,ป.4,ป.5,ป.6`
   - ลำดับนี้ใช้ตอนเลื่อนชั้น ชั้นสุดท้ายในรายการจะ **จบการศึกษา**
2. ตรวจเมนู **ปีการศึกษา** ว่าปีปัจจุบันถูกต้อง (ปีการศึกษาไทยเริ่ม 16 พฤษภาคม)
3. เจ้าหน้าที่การเงินนำเข้ารายชื่อนักเรียน (ดูหัวข้อ [ทดสอบระยะที่ 3](#ทดสอบระยะที่-3-ด้วยมือ))

## ตรวจผลการติดตั้ง

- [ ] มีแท็บชีตครบ 15 ชีต และแถวแรกเป็นหัวตารางสีกรมท่า
- [ ] ชีต `SchoolSettings` มี 23 แถว

## ทดสอบระยะที่ 2 ด้วยมือ

ทดสอบก่อนใช้งานจริง

- บัญชีที่สร้างเพื่อทดสอบลบไม่ได้ (ระบบไม่มีการลบผู้ใช้)
- แนะนำให้ทดสอบด้วยบัญชีของผู้ที่จะใช้งานจริง หรือปิดการใช้งานบัญชีทดสอบหลังทดสอบเสร็จ
- ใช้หน้าต่างไม่ระบุตัวตน (Incognito) เพื่อเข้าสู่ระบบหลายบัญชีพร้อมกัน

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | เปิดลิงก์เว็บแอป | หน้าเข้าสู่ระบบแสดงชื่อโรงเรียน |
| 2 | ใส่รหัสผ่านผิด | "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" |
| 3 | เข้าสู่ระบบด้วยผู้ดูแลระบบ | หน้าหลักแสดง "เริ่มต้นใช้งาน" และเมนูผู้ใช้งาน ประวัติการใช้งาน ตั้งค่าโรงเรียน ปีการศึกษา |
| 4 | เมนูผู้ใช้งาน → เพิ่มผู้ใช้ เจ้าหน้าที่การเงิน 1 คน และผู้อำนวยการ 1 คน | ผู้ใช้ใหม่ขึ้นในตาราง สถานะ "รอเปลี่ยนรหัสผ่าน" |
| 5 | เมนูตั้งค่าโรงเรียน → กรอกที่อยู่และชื่อผู้อำนวยการ → บันทึก | "บันทึกค่าตั้งค่า 2 รายการเรียบร้อยแล้ว" |
| 6 | เข้าสู่ระบบด้วยเจ้าหน้าที่การเงิน (หน้าต่าง Incognito) | ต้องตั้งรหัสผ่านใหม่ก่อน แล้วเห็นเฉพาะเมนูหน้าหลัก ตั้งค่าโรงเรียน ปีการศึกษา |
| 7 | (เจ้าหน้าที่การเงิน) เปิดตั้งค่าโรงเรียน | ทุกช่องแก้ไขไม่ได้ และขึ้นข้อความ "เฉพาะผู้ดูแลระบบเท่านั้นที่แก้ไขค่าตั้งค่าได้" |
| 8 | ใส่รหัสผ่านผิด 5 ครั้งด้วยชื่อผู้ใช้เดียวกัน | ครั้งที่ 5 แจ้งว่าถูกล็อกชั่วคราว ประมาณ 15 นาที |
| 9 | ผู้ดูแลระบบกด "รีเซ็ตรหัสผ่าน" ให้บัญชีที่ถูกล็อก | เข้าสู่ระบบด้วยรหัสผ่านชั่วคราวใหม่ได้ทันที |
| 10 | ผู้ดูแลระบบแก้ไขบัญชีทดสอบ → สถานะ "ปิดการใช้งาน" | ผู้ใช้นั้นถูกพากลับหน้าเข้าสู่ระบบเมื่อกดเมนูถัดไป |
| 11 | เข้าสู่ระบบด้วยผู้อำนวยการ → ประวัติการใช้งาน → ตรวจความถูกต้องของประวัติ | เห็นการเข้าสู่ระบบและการแก้ไขทั้งหมด และผลตรวจ "ถูกต้อง" |
| 12 | คลิกแถวประวัติที่เป็น "แก้ไข" | เห็นค่าเดิมและค่าใหม่ ช่องรหัสผ่านแสดงเป็น "[ซ่อน]" |
| 13 | เปิดลิงก์บนมือถือ | กดปุ่ม ≡ แล้วเมนูเลื่อนออกมา ตารางแสดงเป็นการ์ด |
| 14 | ทิ้งไว้ไม่ใช้งาน 30 นาที แล้วกดเมนู | ต้องเข้าสู่ระบบใหม่ |

## ทดสอบระยะที่ 3 ด้วยมือ

ใช้รายชื่อนักเรียนจริงได้เลย ข้อมูลที่นำเข้าแล้วแก้ไขหรือเปลี่ยนสถานะได้ แต่ลบไม่ได้ (เพื่อเก็บประวัติ)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | ผู้ดูแลระบบ → ตั้งค่าโรงเรียน → ตรวจ **ระดับชั้นที่เปิดสอน** | ตรงกับชั้นที่โรงเรียนเปิดสอนจริง |
| 2 | เจ้าหน้าที่การเงิน → เมนู **นักเรียน** → **เพิ่มนักเรียน** 1 คน | ขึ้นในตาราง เรียงตามชั้น ห้อง และเลขที่ |
| 3 | เพิ่มนักเรียนโดยไม่เลือกระดับชั้น | "กรุณาเลือกระดับชั้น" |
| 4 | เพิ่มนักเรียนเลขประจำตัวซ้ำกับข้อ 2 | "เลขประจำตัว … เป็นของ … อยู่แล้ว" และไม่บันทึก |
| 5 | เพิ่มนักเรียนชื่อ-นามสกุลซ้ำกับข้อ 2 แต่เลขประจำตัวต่างกัน | ระบบเตือนว่ามีชื่อนี้แล้ว ต้องกด **ยืนยัน เป็นคนละคน** จึงบันทึก |
| 6 | **นำเข้าจาก Excel/CSV** → เลือกไฟล์รายชื่อ .xlsx หรือ .csv (หรือกด **ดาวน์โหลดแบบฟอร์ม CSV**) | ระบบจับคู่คอลัมน์ให้เอง แก้ได้ในขั้นที่ 2 |
| 7 | กด **ตรวจสอบข้อมูล** | แสดงจำนวน นักเรียนใหม่ / ไม่มีการเปลี่ยนแปลง / ข้อมูลไม่ถูกต้อง พร้อมเหตุผลรายแถว ยังไม่บันทึก |
| 8 | กด **นำเข้า N รายการ** → ยืนยัน | "นำเข้าข้อมูลเรียบร้อย" แถวที่ไม่ถูกต้องถูกข้าม |
| 9 | นำเข้าไฟล์เดิมซ้ำอีกครั้ง | ทุกแถวเป็น "ไม่มีการเปลี่ยนแปลง" ไม่มีนักเรียนซ้ำเพิ่มขึ้น |
| 10 | ช่อง **ค้นหา** พิมพ์ชื่อ นามสกุล หรือเลขประจำตัว | เหลือเฉพาะคนที่ตรง |
| 11 | กด **สถานะ** → ย้ายออก → ใส่หมายเหตุ → บันทึก | หายจากรายการ "กำลังศึกษา" เลือกตัวกรองสถานะ "ย้ายออก" แล้วเห็น |
| 12 | คลิกชื่อนักเรียน | เห็นประวัติชั้นเรียนทุกปี |
| 13 | **เลื่อนชั้นขึ้นปีใหม่** → เลือกปี → **ดูตัวอย่างการเลื่อนชั้น** (ยังไม่ต้องกดยืนยัน) | แสดงจำนวนที่จะเลื่อนชั้นแต่ละชั้น และชั้นสุดท้ายเป็น "จบการศึกษา" |
| 14 | เข้าสู่ระบบด้วยผู้อำนวยการ → นักเรียน | ดูรายชื่อได้ แต่ไม่มีปุ่มเพิ่ม นำเข้า แก้ไข หรือเลื่อนชั้น |
| 15 | ผู้อำนวยการ → ประวัติการใช้งาน | เห็นการเพิ่ม นำเข้า และเปลี่ยนสถานะนักเรียน พร้อมชื่อผู้ทำ |

> ⚠️ **กดยืนยันเลื่อนชั้นจริงเมื่อปิดภาคเรียนสุดท้ายของปีแล้วเท่านั้น**
> - ต้องให้ผู้ดูแลระบบสร้างปีการศึกษาใหม่ก่อน
> - ข้อมูลปีเดิมไม่ถูกลบ และกดซ้ำได้โดยไม่เกิดรายชื่อซ้ำ
> - ห้องและเลขที่ในปีใหม่คงเดิม แก้ภายหลังได้ หรือนำเข้ารายชื่อปีใหม่พร้อมติ๊ก "ปรับปรุงข้อมูลนักเรียนเดิมตามไฟล์"

### เตรียมไฟล์รายชื่อนักเรียน

- รองรับ **.xlsx** (Excel), **.csv** และการคัดลอกตารางจาก Excel/Google Sheets มาวาง
- ไฟล์ **.xls** (Excel รุ่นเก่า) ให้เปิดใน Excel แล้วบันทึกเป็น .xlsx ก่อน
- ต้องมีอย่างน้อยคอลัมน์ **เลขประจำตัวนักเรียน**, **ชื่อ** (หรือ ชื่อ-นามสกุล ในช่องเดียว) และ **ชั้น**
- ชั้นเขียนได้หลายแบบ เช่น `ป.1/2`, `ป.1` กับห้อง `2` แยกคอลัมน์, `ประถมศึกษาปีที่ 1/2`
- แถวหัวตารางไม่จำเป็นต้องอยู่แถวแรก (ระบบหาเองใน 10 แถวแรก)
- นำเข้าได้ครั้งละไม่เกิน 1,500 แถว

## ทางเลือก: เข้าสู่ระบบด้วยบัญชี Google ของโรงเรียน

ใช้ได้เมื่อเจ้าของระบบและผู้ใช้ทุกคนมีบัญชีใน Google Workspace โดเมนเดียวกัน (ดูเหตุผลใน ARCHITECTURE.md หัวข้อ 3)

1. ผู้ดูแลระบบกรอก **อีเมล** ของผู้ใช้ทุกคนให้ตรงกับบัญชี Google ของโรงเรียน
2. Apps Script → ⚙️ การตั้งค่าโปรเจกต์ → Script Properties → แก้ `AUTH_MODE` เป็น `GOOGLE`
3. Deploy → Manage deployments → ✏️ → Who has access = **Anyone within (ชื่อโดเมนโรงเรียน)** → Version: New version → Deploy

หลังเปลี่ยน ผู้ใช้กดปุ่ม "เข้าสู่ระบบด้วยบัญชี Google ของโรงเรียน" และไม่ต้องมีรหัสผ่านของระบบ

## สำหรับผู้พัฒนา

### โครงสร้างโค้ด

- ซอร์สโค้ดแยกไฟล์อยู่ใน `src/` แก้ไขที่นี่เท่านั้น
- `dist/Code.gs` สร้างจาก `src/` อัตโนมัติ รวมหน้าเว็บ HTML ไว้ในไฟล์ด้วย ห้ามแก้โดยตรง

```bash
npm run build
```

### ชุดทดสอบ

ต้องมี Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm test
```

ทดสอบหน้าเว็บจริงใน Chromium (ต้องมี Playwright) และบันทึกภาพหน้าจอไว้ที่ `docs/screenshots/`:

```bash
npm run test:e2e
```

- `npm test` รันโค้ดจริงใน `src/` กับ Google Sheets จำลอง (`tests/harness.js`) ครอบคลุมสิทธิ์ทุกคำสั่งกับทุกบทบาท
- `npm run test:e2e` ใช้หน้าเว็บที่ `doGet()` สร้างจริง ต่อกับ Server จำลอง แล้วกดใช้งานจริงทั้งบนคอมพิวเตอร์และมือถือ

### ทางเลือก: ติดตั้งแบบแยกไฟล์หรือด้วย clasp

**แยกไฟล์:**
1. สร้างไฟล์ Script ตามชื่อไฟล์ `.js` ใน `src/`
2. สร้างไฟล์ HTML ตามชื่อไฟล์ `.html` ใน `src/` (เมนู + → HTML)
3. วางเนื้อหาทีละไฟล์

**clasp:**

1. ติดตั้งและเข้าสู่ระบบ

   ```bash
   npm install -g @google/clasp
   ```

   ```bash
   clasp login
   ```

2. คัดลอก `.clasp.json.example` เป็น `.clasp.json` แล้วใส่ Script ID
3. อัปโหลดทั้งโฟลเดอร์ `src/`

   ```bash
   clasp push
   ```
