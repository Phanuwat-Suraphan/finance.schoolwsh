# คู่มือติดตั้งและทดสอบ

ระบบบริหารจัดเก็บเงินบำรุงการศึกษา โรงเรียนวัดเสาหิน จังหวัดเชียงใหม่

> ปัจจุบันครอบคลุมถึง **ระยะที่ 6: ระบบยอดค้างชำระ** (ยอดค้างรายนักเรียน รายห้อง รายชั้น ทั้งโรงเรียน และยอดค้างสะสมจากปีก่อน)
> ทั้งระบบอยู่ในไฟล์เดียวคือ [`dist/Code.gs`](../dist/Code.gs) ทั้งการติดตั้งครั้งแรกและการอัปเดตใช้วิธีวางไฟล์เดียวเหมือนกัน

---

## เตรียมก่อนเริ่ม

1. **บัญชี Google ที่จะเป็นเจ้าของระบบ**
   - แนะนำบัญชีกลางของโรงเรียน ไม่ใช่บัญชีส่วนตัวของครู
   - เปิด 2-Step Verification
2. **ไฟล์ Google Sheets ที่สร้างไว้** เปิดด้วยบัญชีเจ้าของระบบ
3. **ใช้คอมพิวเตอร์** และให้เบราว์เซอร์ login บัญชี Google ไว้เพียงบัญชีเดียว
   - ถ้า login หลายบัญชี Google อาจรันสคริปต์ด้วยบัญชีอื่นแล้วเกิดข้อผิดพลาดเรื่องสิทธิ์
   - วิธีง่ายที่สุด: เปิด **หน้าต่างไม่ระบุตัวตน (Incognito)** ด้วย Ctrl+Shift+N แล้ว login เฉพาะบัญชีเจ้าของระบบ

## ติดตั้งครั้งแรก (6 ขั้นตอน)

### 1. เปิด Apps Script

ใน Google Sheets ไปที่เมนู **ส่วนขยาย (Extensions) → Apps Script**

### 2. คัดลอกโค้ด

1. เปิดไฟล์ [`dist/Code.gs`](../dist/Code.gs) บน GitHub
2. กดปุ่ม **Copy raw file** (ไอคอนสี่เหลี่ยมซ้อน มุมขวาบนของกล่องโค้ด)

### 3. วางโค้ด

1. ในหน้า Apps Script คลิกในไฟล์ `Code.gs`
2. กด **Ctrl+A** แล้ว **Ctrl+V** (วางทับทั้งหมด)
3. กด **Ctrl+S** (บันทึก)

บน Mac ใช้ ⌘ แทน Ctrl

### 4. ติดตั้งฐานข้อมูล

1. ช่องรายชื่อฟังก์ชันด้านบนต้องเป็น **`SetupDatabase`** → กด **▶ เรียกใช้ (Run)**
2. ครั้งแรก Google จะขออนุญาต:
   1. กด **ตรวจสอบสิทธิ์ (Review permissions)** → เลือกบัญชีเจ้าของระบบ
   2. ถ้าเห็นข้อความว่า Google ยังไม่ได้ยืนยันแอปนี้ ให้กด **ขั้นสูง (Advanced)** → **ไปที่ … (ไม่ปลอดภัย)**
      ข้อความนี้ปรากฏกับสคริปต์ที่โรงเรียนเขียนเองทุกตัว
   3. ถ้าหน้าขออนุญาตมี**ช่องให้ติ๊กทีละสิทธิ์** ให้ติ๊ก **เลือกทั้งหมด (Select all)** ให้ครบทุกข้อก่อน
      ถ้าไม่ติ๊กบางข้อ ระบบจะสำรองข้อมูลอัตโนมัติไม่ได้
   4. กด **อนุญาต (Allow)** หรือ **ดำเนินการต่อ (Continue)**
   - รายการสิทธิ์ที่ขอ: Google Sheets (ฐานข้อมูล), Google Drive (สร้างไฟล์สำรองข้อมูลในโฟลเดอร์ของระบบ), การทำงานเมื่อไม่ได้เปิดใช้ (สำรองข้อมูลอัตโนมัติรายวัน) และอีเมลของบัญชีที่ใช้
3. ถ้ารอบแรกหยุดไปเพราะขออนุญาต ให้กด **▶ เรียกใช้** อีกครั้ง
4. ช่อง **บันทึกการดำเนินการ (Execution log)** ด้านล่างต้องแสดง **สร้างชีตใหม่ 16 ชีต**, **สร้างปีการศึกษาเริ่มต้น 2569** และ **ตั้งเวลาสำรองข้อมูลอัตโนมัติทุกวัน เวลาประมาณ 18:00–19:00 น.**

### 5. สร้างผู้ดูแลระบบคนแรก

ทำครั้งเดียว โดยบัญชีเจ้าของไฟล์เท่านั้น (บัญชีผู้ใช้อื่นสร้างในหน้าเว็บ ดูข้อ 6)

1. กลับไปที่ **Google Sheets** (ไม่ใช่หน้าเว็บแอป) แล้วกด **F5** (รีเฟรช)
2. รอ 5–10 วินาที จนเมนู **ระบบเงินบำรุงการศึกษา** ปรากฏที่แถบเมนูด้านบน (ต่อจากเมนู "ความช่วยเหลือ")
3. เลือกเมนู **ระบบเงินบำรุงการศึกษา → 3) สร้างหรือรีเซ็ตบัญชีผู้ดูแลระบบ**
   - ถ้า Google ขออนุญาตอีกครั้ง ให้อนุญาตแบบเดียวกับขั้นตอนที่ 4 แล้วเลือกเมนูนี้ซ้ำ
4. กรอกในหน้าต่างที่ปรากฏ:

   | ช่อง | กรอก |
   |---|---|
   | ชื่อผู้ใช้ | ภาษาอังกฤษตัวพิมพ์เล็ก เช่น `admin` |
   | ชื่อ-นามสกุล | ชื่อของผู้ดูแลระบบ |
   | อีเมล | เว้นว่างได้ |
   | รหัสผ่าน และ ยืนยันรหัสผ่าน | อย่างน้อย 8 ตัว มีทั้งตัวอักษรและตัวเลข และต้องไม่มีชื่อผู้ใช้อยู่ในรหัสผ่าน (ชื่อผู้ใช้ `admin` ใช้ `Admin2569` ไม่ได้ แต่ใช้ `Saohin2569` ได้) |
   | ให้เปลี่ยนรหัสผ่านเมื่อเข้าสู่ระบบครั้งแรก | ติ๊กไว้ถ้าสร้างให้คนอื่น / เอาติ๊กออกได้ถ้าสร้างให้ตัวเอง |

5. กด **บันทึก** → ต้องขึ้นข้อความ **สร้างบัญชีผู้ดูแลระบบ "admin" เรียบร้อยแล้ว**

ถ้าไม่เห็นเมนู หรือกดบันทึกแล้วขึ้นว่าเชื่อมต่อไม่สำเร็จ ดูตาราง [ปัญหาที่พบบ่อย](#ปัญหาที่พบบ่อย)

### 6. เผยแพร่เว็บแอป

1. ในหน้า Apps Script กดปุ่ม **Deploy (ทำให้ใช้งานได้)** มุมขวาบน → **New deployment (การทำให้ใช้งานได้รายการใหม่)**
2. กดรูปเฟือง ⚙ ข้าง **Select type** → เลือก **Web app (เว็บแอป)**
3. ตั้งค่า:

   | ช่อง | ค่าที่ต้องเลือก | เหตุผล |
   |---|---|---|
   | Description | `ระยะที่ 6` | ชื่อเวอร์ชัน |
   | Execute as | **Me (อีเมลเจ้าของระบบ)** | ผู้ใช้ไม่ต้องมีสิทธิ์ในไฟล์ Google Sheets จึงแก้ข้อมูลข้ามระบบไม่ได้ |
   | Who has access | **Anyone with Google account** | ต้องลงชื่อเข้าใช้ Google ก่อนจึงเห็นหน้าเข้าสู่ระบบ |

   ⚠️ **ห้ามเลือก Execute as = User accessing the web app** เพราะต้องแชร์ไฟล์ให้ทุกคน และทุกคนจะแก้ตัวเลขในชีตได้โดยตรง

4. กด **Deploy** (ถ้าขออนุญาต ให้อนุญาต)
5. คัดลอก **Web app URL** (ลงท้ายด้วย `/exec`) ลิงก์นี้คือที่อยู่ของระบบ ใช้ส่งให้ผู้ใช้
6. เปิดลิงก์ → เข้าสู่ระบบด้วยบัญชีผู้ดูแลระบบ → ทำตามรายการ **เริ่มต้นใช้งาน** ในหน้าหลัก:
   1. กรอกข้อมูลโรงเรียนและชื่อผู้ลงนาม
   2. เพิ่มผู้ใช้เจ้าหน้าที่การเงินและผู้อำนวยการ
   3. ตรวจปีการศึกษาปัจจุบัน

> ผู้ใช้ทุกคนต้องลงชื่อเข้าใช้ Google (บัญชีใดก็ได้) ในเบราว์เซอร์ก่อน แล้วจึงเข้าสู่ระบบของโรงเรียนด้วยชื่อผู้ใช้และรหัสผ่านที่ผู้ดูแลระบบสร้างให้

## อัปเดตเมื่อมีเวอร์ชันใหม่

1. ทำ **ขั้นตอนที่ 2–4** ของการติดตั้ง (คัดลอก → วางทับทั้งหมด → บันทึก → Run `SetupDatabase`)
2. **Deploy → Manage deployments (จัดการการทำให้ใช้งานได้)** → เลือกรายการเดิม → กดรูปดินสอ ✏️
3. ช่อง **Version** เลือก **New version (เวอร์ชันใหม่)** → กด **Deploy**

- ลิงก์ `/exec` เดิมใช้ได้ต่อ ข้อมูลเดิมไม่หาย
- ถ้าข้ามข้อ 2–3 เว็บแอปจะยังเป็นเวอร์ชันเก่า
- **ถ้าติดตั้งระยะที่ 1 ไว้แล้ว:** อัปเดตตามข้อ 1 แล้วทำขั้นตอนที่ 5–6 ของการติดตั้งครั้งแรก
- ตรวจว่าอัปเดตสำเร็จ: ด้านล่างหน้าเข้าสู่ระบบแสดง **เวอร์ชัน 1.0.1** และหน้าหลักแสดง **ระยะที่ 8 จาก 8**

### หลังอัปเดตเป็นระยะที่ 3

1. ผู้ดูแลระบบเปิดเมนู **ตั้งค่าโรงเรียน** → ตรวจช่อง **ระดับชั้นที่เปิดสอน** ให้ตรงกับโรงเรียนจริง เรียงจากชั้นต่ำไปสูง คั่นด้วยจุลภาค
   - ค่าเริ่มต้นคือ `อ.1,อ.2,อ.3,ป.1,ป.2,ป.3,ป.4,ป.5,ป.6`
   - ถ้าโรงเรียนไม่มี อ.1 ให้ลบออก เช่น `อ.2,อ.3,ป.1,ป.2,ป.3,ป.4,ป.5,ป.6`
   - ลำดับนี้ใช้ตอนเลื่อนชั้น ชั้นสุดท้ายในรายการจะ **จบการศึกษา**
2. ตรวจเมนู **ปีการศึกษา** ว่าปีปัจจุบันถูกต้อง (ปีการศึกษาไทยเริ่ม 16 พฤษภาคม)
3. เจ้าหน้าที่การเงินนำเข้ารายชื่อนักเรียน (ดูหัวข้อ [ทดสอบระยะที่ 3](#ทดสอบระยะที่-3-ด้วยมือ))

### หลังอัปเดตเป็นระยะที่ 4

> ข้อมูลการเงินที่บันทึกแล้วลบไม่ได้ (ตามข้อกำหนด) ให้ฝึกใช้ใน [ชุดทดสอบแยก](#ติดตั้งชุดทดสอบแยก-แนะนำก่อนบันทึกเงินจริง) ก่อนบันทึกเงินจริง

1. ผู้ดูแลระบบเปิดเมนู **ตั้งค่าโรงเรียน** ตรวจ:
   - **ช่องทางการรับเงิน** (ค่าเริ่มต้น: เงินสด, โอนเงินเข้าบัญชีโรงเรียน) ช่องทางที่ไม่ใช่เงินสดต้องกรอกเลขอ้างอิงทุกครั้ง
   - **รายการที่ต้องให้ผู้อำนวยการอนุมัติ** (ค่าเริ่มต้น: ต้องอนุมัติทุกรายการ)
   - **ใบเสร็จรับเงิน**: เตือนเมื่อเลขที่เหลือน้อย และใช้เลขที่เรียงลำดับเคร่งครัด (แนะนำให้เปิดไว้)
2. ลำดับการใช้งานของเจ้าหน้าที่การเงิน:
   **อัตราและการเรียกเก็บ** (ตั้งอัตรา + เอกสารที่อนุมัติ → สร้างรายการเรียกเก็บ) → **เล่มใบเสร็จ** (ลงทะเบียน → เปิดใช้) → **รับชำระเงิน**

### หลังอัปเดตเป็นระยะที่ 5

ระยะนี้เพิ่มเครื่องมือแก้ไขหลังบันทึก ทุกอย่างไม่ลบข้อมูล มีประวัติ และรอผู้อำนวยการอนุมัติตามการตั้งค่า:

| สถานการณ์ | ใช้เมนู |
|---|---|
| ใบเสร็จเขียนผิดหรือชำรุด และ**ยังไม่ได้บันทึกรับเงิน** | หน้ารับชำระเงิน → ปุ่ม "ใบเสร็จเลขที่ … เขียนผิดหรือชำรุด? ยกเลิกเลขที่นี้" หรือ เล่มใบเสร็จ → คลิกเล่ม → คลิกเลขที่ |
| ใบเสร็จที่บันทึกรับเงินแล้ว ต้อง**ยกเลิกทั้งฉบับ** | รายการรับเงิน หรือบัญชีนักเรียน → คลิกรายการ → **ขอยกเลิกใบเสร็จ** |
| ใบเสร็จจริงถูกต้อง แต่**บันทึกในระบบผิด** (จำนวนเงิน วันที่ ช่องทาง นักเรียน รายการที่ตัดชำระ) | คลิกรายการรับเงิน → **ขอแก้ไขรายการ** (เลขที่ใบเสร็จไม่เปลี่ยน) |
| เล่มชำรุดหรือต้อง**ปิดเล่มก่อนใช้ครบ** | เล่มใบเสร็จ → คลิกเล่ม → **ขอปิดเล่มก่อนใช้ครบ** |

> **ก่อนเริ่มใช้จริง**
> - ให้เจ้าหน้าที่การเงินและผู้อำนวยการตรวจ [แบบตรวจยืนยันใน DECISIONS.md](DECISIONS.md#แบบตรวจยืนยันก่อนใช้งานจริง-สำหรับผู้มีหน้าที่การเงิน)
> - ตั้งแต่ระยะที่ 7 ระบบสำรองข้อมูลอัตโนมัติทุกวัน (ดู [หลังอัปเดตเป็นระยะที่ 7](#หลังอัปเดตเป็นระยะที่-7))

### หลังอัปเดตเป็นระยะที่ 6

เมนูใหม่ **การเงิน → ยอดค้างชำระ** (เจ้าหน้าที่การเงินและผู้อำนวยการ) และหน้าหลักแสดง "ยอดค้างทั้งหมด"

| ยอด | ความหมาย |
|---|---|
| ค้างปีนี้ | ยอดค้างของรายการเรียกเก็บในปีการศึกษาที่เลือก |
| ค้างจากปีก่อน | ยอดค้างสะสมของรายการเรียกเก็บปีการศึกษาก่อนหน้า |
| รวมค้าง | ยอดค้างทุกปีของนักเรียนคนนั้น |
| เลยกำหนด | ยอดค้างของรายการที่เลยวันครบกำหนดชำระแล้ว |

- นักเรียนที่ย้ายออกหรือจบการศึกษาแล้วแต่ยังมียอดค้าง แสดงแยกเป็นกลุ่ม "ไม่มีชั้นเรียนในปีนี้" และยังนับในยอดรวมทั้งโรงเรียน
- กดปุ่ม **พิมพ์** เพื่อพิมพ์หรือบันทึกเป็น PDF (เลือกเครื่องพิมพ์ "บันทึกเป็น PDF") หน้าพิมพ์มีชื่อโรงเรียน วันเวลาของข้อมูล และเงื่อนไขที่เลือก
- รายงานแบบทางการพร้อมช่องลงนาม และหนังสือแจ้งยอดถึงผู้ปกครอง อยู่ในเมนู **รายงานและปิดยอด** (ระยะที่ 7)

### หลังอัปเดตเป็นระยะที่ 7

ระยะนี้ขอสิทธิ์เพิ่ม 2 อย่าง จึง**ต้องกดอนุญาตใหม่ 1 ครั้ง**:

| สิทธิ์ที่ Google ขอเพิ่ม | ใช้ทำอะไร |
|---|---|
| ดู แก้ไข สร้าง และลบไฟล์ใน Google ไดรฟ์ | สร้างไฟล์สำรองข้อมูลในโฟลเดอร์ของระบบ และย้ายไฟล์สำรองอัตโนมัติที่เก่าเกินกำหนดไปถังขยะ (ใช้บริการ DriveApp ในตัวของ Apps Script ไม่ส่งข้อมูลออกนอก Google) |
| เรียกใช้เมื่อคุณไม่ได้อยู่ / จัดการทริกเกอร์ | สำรองข้อมูลอัตโนมัติทุกวัน และให้ผู้ดูแลระบบเปิด/ปิดหรือเปลี่ยนเวลาได้จากหน้าเว็บ |

1. อัปเดตโค้ดตามข้อ 1 ของหัวข้อด้านบน เมื่อกด **▶ เรียกใช้ `SetupDatabase`** Google จะขออนุญาตใหม่ ให้กด **ตรวจสอบสิทธิ์ → ขั้นสูง → ไปที่ … → ติ๊ก "เลือกทั้งหมด (Select all)" → ดำเนินการต่อ**
2. Execution log ต้องแสดง:
   - **สร้างชีตใหม่ 1 ชีต: DailyClosings** (การปิดยอดประจำวัน)
   - **เพิ่มค่าตั้งค่าเริ่มต้น** (เบอร์โทรศัพท์ติดต่อ และการอยู่ในระบบต่อ)
   - **ตั้งเวลาสำรองข้อมูลอัตโนมัติทุกวัน เวลาประมาณ 18:00–19:00 น.**
3. ทำข้อ 2–3 ของการอัปเดต (**New version** → Deploy) ถ้าข้ามข้อนี้ หน้าเว็บจะสำรองข้อมูลไม่ได้
4. ผู้ดูแลระบบ:
   1. เมนู **ตั้งค่าโรงเรียน** → กรอก **ที่อยู่โรงเรียน**, **เบอร์โทรศัพท์ติดต่อ** และ **ชื่อ/ตำแหน่งผู้ลงนาม** ให้ครบ (ใช้ในรายงานและหนังสือแจ้งยอด)
   2. เมนู **สำรองและกู้คืนข้อมูล** → กด **สำรองข้อมูลตอนนี้** เพื่อสร้างไฟล์สำรองแรก
   3. เจ้าของระบบเปิด Google Drive ต้องเห็นโฟลเดอร์ **สำรองข้อมูล ระบบเงินบำรุงการศึกษา – (ชื่อไฟล์ฐานข้อมูล)** และไฟล์สำรองข้างใน **ห้ามแชร์โฟลเดอร์นี้**
5. งานประจำวันของเจ้าหน้าที่การเงิน (ใหม่): สิ้นวัน → **รายงานและปิดยอด** → **รายงานการรับเงินประจำวัน** → พิมพ์ → ตรวจกับเงินและสำเนาใบเสร็จ → ลงนาม → กด **ปิดยอดวันนี้**
   - หลังปิดยอด บันทึกรับเงิน ขอยกเลิก หรือขอแก้ไขรายการของวันนั้นไม่ได้ ถ้าจำเป็น ผู้อำนวยการกด **เปิดยอดใหม่** พร้อมเหตุผล (D-37)
6. ผู้อำนวยการดูภาพรวมได้ที่เมนู **ภาพรวม (Dashboard)**

| เมนูใหม่ | ผู้ใช้ | ใช้ทำอะไร |
|---|---|---|
| ภาพรวม (Dashboard) | การเงิน, ผู้อำนวยการ | ยอดเรียกเก็บ ยอดรับ ยอดค้าง จำนวนผู้ชำระครบ/บางส่วน/ยังไม่ชำระ และกราฟรายชั้น/ห้อง เลือกปีการศึกษาได้ |
| รายงานและปิดยอด | การเงิน, ผู้อำนวยการ | รายงาน 9 ฉบับ พิมพ์หรือบันทึกเป็น PDF ได้ และปิดยอดประจำวัน |
| สำรองและกู้คืนข้อมูล | ผู้ดูแลระบบ | สำรองทันที ตั้งเวลาสำรองอัตโนมัติ และกู้คืน |

> **บันทึกเป็น PDF:** กดปุ่ม **พิมพ์ / บันทึก PDF** → ในหน้าต่างพิมพ์ ช่องปลายทาง (Destination) เลือก **บันทึกเป็น PDF (Save as PDF)** → กด **บันทึก**
> แนะนำให้ตั้งขนาดกระดาษ A4 และปิด "ส่วนหัวและส่วนท้าย (Headers and footers)" ในหน้าต่างพิมพ์

### ติดตั้งชุดทดสอบแยก (แนะนำก่อนบันทึกเงินจริง)

ข้อมูลการเงินลบไม่ได้ จึงควรลองใช้ในระบบชุดที่ 2 ที่แยกจากของจริงทั้งหมด

1. สร้าง **Google Sheets ไฟล์ใหม่** (ไฟล์เปล่า ไม่ใช่การทำสำเนาไฟล์เดิม) ตั้งชื่อเช่น `ทดสอบระบบเงินบำรุง`
2. ทำ **ขั้นตอนที่ 1–6** ของการติดตั้งครั้งแรกกับไฟล์ใหม่นี้ จะได้ลิงก์เว็บแอปของชุดทดสอบแยกต่างหาก
3. ทดสอบด้วยรายชื่อนักเรียนสมมติ และเล่มใบเสร็จสมมติ
4. เมื่ออัปเดตเวอร์ชันใหม่ ให้อัปเดตทั้ง 2 ชุด
5. ชุดทดสอบก็สำรองข้อมูลอัตโนมัติทุกวันเช่นกัน (โฟลเดอร์แยก ชื่อมีชื่อไฟล์ทดสอบต่อท้าย) ถ้าไม่ต้องการ ให้ผู้ดูแลระบบของชุดทดสอบปิดในหน้า **สำรองและกู้คืนข้อมูล → ตั้งเวลาสำรองอัตโนมัติ**

> ไม่ใช้วิธี **ทำสำเนา (Make a copy)** ไฟล์เดิม เพราะสคริปต์ในไฟล์สำเนาอาจยังชี้ไปที่ฐานข้อมูลของไฟล์จริง

## ทดสอบระยะที่ 2 ด้วยมือ

ทดสอบก่อนใช้งานจริง

- บัญชีที่สร้างเพื่อทดสอบลบไม่ได้ (ระบบไม่มีการลบผู้ใช้)
- แนะนำให้ทดสอบด้วยบัญชีของผู้ที่จะใช้งานจริง หรือปิดการใช้งานบัญชีทดสอบหลังทดสอบเสร็จ
- ใช้หน้าต่างไม่ระบุตัวตน (Incognito) เพื่อเข้าสู่ระบบหลายบัญชีพร้อมกัน

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | เปิดลิงก์เว็บแอป | หน้าเข้าสู่ระบบแสดงชื่อโรงเรียน |
| 2 | ใส่รหัสผ่านผิด | "ชื่อผู้ใช้หรือรหัสผ่านไม่ถูกต้อง" |
| 3 | เข้าสู่ระบบด้วยผู้ดูแลระบบ | หน้าหลักแสดง "เริ่มต้นใช้งาน" และเมนูผู้ใช้งาน ประวัติการใช้งาน ตั้งค่าโรงเรียน ปีการศึกษา |
| 4 | เมนูผู้ใช้งาน → เพิ่มผู้ใช้ เจ้าหน้าที่การเงิน 1 คน และผู้อำนวยการ 1 คน | ผู้ใช้ใหม่ขึ้นในตาราง สถานะ "รอเปลี่ยนรหัสผ่าน" |
| 5 | เมนูตั้งค่าโรงเรียน → กรอกที่อยู่และชื่อผู้อำนวยการ → บันทึก | "บันทึกค่าตั้งค่า 2 รายการเรียบร้อยแล้ว" |
| 6 | เข้าสู่ระบบด้วยเจ้าหน้าที่การเงิน (หน้าต่าง Incognito) | ต้องตั้งรหัสผ่านใหม่ก่อน แล้วเห็นเฉพาะเมนูหน้าหลัก ตั้งค่าโรงเรียน ปีการศึกษา |
| 7 | (เจ้าหน้าที่การเงิน) เปิดตั้งค่าโรงเรียน | ทุกช่องแก้ไขไม่ได้ และขึ้นข้อความ "เฉพาะผู้ดูแลระบบเท่านั้นที่แก้ไขค่าตั้งค่าได้" |
| 8 | ใส่รหัสผ่านผิด 5 ครั้งด้วยชื่อผู้ใช้เดียวกัน | ครั้งที่ 5 แจ้งว่าถูกล็อกชั่วคราว ประมาณ 15 นาที |
| 9 | ผู้ดูแลระบบกด "รีเซ็ตรหัสผ่าน" ให้บัญชีที่ถูกล็อก | เข้าสู่ระบบด้วยรหัสผ่านชั่วคราวใหม่ได้ทันที |
| 10 | ผู้ดูแลระบบแก้ไขบัญชีทดสอบ → สถานะ "ปิดการใช้งาน" | ผู้ใช้นั้นถูกพากลับหน้าเข้าสู่ระบบเมื่อกดเมนูถัดไป |
| 11 | เข้าสู่ระบบด้วยผู้อำนวยการ → ประวัติการใช้งาน → ตรวจความถูกต้องของประวัติ | เห็นการเข้าสู่ระบบและการแก้ไขทั้งหมด และผลตรวจ "ถูกต้อง" |
| 12 | คลิกแถวประวัติที่เป็น "แก้ไข" | เห็นค่าเดิมและค่าใหม่ ช่องรหัสผ่านแสดงเป็น "[ซ่อน]" |
| 13 | เปิดลิงก์บนมือถือ | กดปุ่ม ≡ แล้วเมนูเลื่อนออกมา ตารางแสดงเป็นการ์ด |
| 14 | ทิ้งไว้ไม่ใช้งาน 30 นาที แล้วกดเมนู | ต้องเข้าสู่ระบบใหม่ |

## ทดสอบระยะที่ 3 ด้วยมือ

ใช้รายชื่อนักเรียนจริงได้เลย ข้อมูลที่นำเข้าแล้วแก้ไขหรือเปลี่ยนสถานะได้ แต่ลบไม่ได้ (เพื่อเก็บประวัติ)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| 1 | ผู้ดูแลระบบ → ตั้งค่าโรงเรียน → ตรวจ **ระดับชั้นที่เปิดสอน** | ตรงกับชั้นที่โรงเรียนเปิดสอนจริง |
| 2 | เจ้าหน้าที่การเงิน → เมนู **นักเรียน** → **เพิ่มนักเรียน** 1 คน | ขึ้นในตาราง เรียงตามชั้น ห้อง และเลขที่ |
| 3 | เพิ่มนักเรียนโดยไม่เลือกระดับชั้น | "กรุณาเลือกระดับชั้น" |
| 4 | เพิ่มนักเรียนเลขประจำตัวซ้ำกับข้อ 2 | "เลขประจำตัว … เป็นของ … อยู่แล้ว" และไม่บันทึก |

| 6 | **นำเข้าจาก Excel/CSV** → เลือกไฟล์รายชื่อ .xlsx หรือ .csv (หรือกด **ดาวน์โหลดแบบฟอร์ม CSV**) | ระบบจับคู่คอลัมน์ให้เอง แก้ได้ในขั้นที่ 2 |

### เตรียมไฟล์รายชื่อนักเรียน

- รองรับ **.xlsx** (Excel), **.csv** และการคัดลอกตารางจาก Excel/Google Sheets มาวาง
- ไฟล์ **.xls** (Excel รุ่นเก่า) ให้เปิดใน Excel แล้วบันทึกเป็น .xlsx ก่อน
- ต้องมีอย่างน้อยคอลัมน์ **เลขประจำตัวนักเรียน**, **ชื่อ** (หรือ ชื่อ-นามสกุล ในช่องเดียว) และ **ชั้น**
- ชั้นเขียนได้หลายแบบ เช่น `ป.1/2`, `ป.1` กับห้อง `2` แยกคอลัมน์, `ประถมศึกษาปีที่ 1/2`
- แถวหัวตารางไม่จำเป็นต้องอยู่แถวแรก (ระบบหาเองใน 10 แถวแรก)
- นำเข้าได้ครั้งละไม่เกิน 1,500 แถว

| 2 | การเงิน | รับเงิน 2–3 ใบ แล้วเปิด **รายงานและปิดยอด → รายงานการรับเงินประจำวัน** | เรียงตามเลขที่ใบเสร็จ ยอดรวมและยอดแยกช่องทางถูกต้อง มีคำว่า "ร่าง – ยังไม่ปิดยอด" |
| 3 | การเงิน | ขอยกเลิกใบเสร็จ 1 ใบของวันนี้ แล้วกลับมาหน้ารายงานประจำวัน | ไม่มีปุ่มปิดยอด และแจ้งว่ามีคำขอรอผู้อำนวยการพิจารณา |
| 4 | ผู้อำนวยการ → การเงิน | พิจารณาคำขอ แล้วการเงินกด **ปิดยอดวันนี้** (ลองกดโดยไม่ติ๊กยืนยันก่อน) | ต้องติ๊กยืนยันก่อน หลังปิดยอดแสดง "ปิดยอดแล้ว" และรหัสตรวจสอบ เช่น `87BA-BB07-C3AE-FFBA` |
| 5 | การเงิน | บันทึกรับเงินโดยใช้วันที่ที่ปิดยอดแล้ว | ระบบไม่รับ แจ้งว่าวันนั้นปิดยอดแล้ว |
| 6 | ผู้อำนวยการ | เปิดรายงานวันนั้น → **เปิดยอดใหม่** (ลองไม่กรอกเหตุผล) | ต้องกรอกเหตุผล หลังเปิดยอด การเงินบันทึกได้และต้องปิดยอดใหม่ รายงานแสดงประวัติการเปิดยอด |
| 7 | การเงิน | พิมพ์รายงานทุกฉบับในหน้ารายงาน (ลองบันทึกเป็น PDF) | ภาษาไทยครบ มีชื่อโรงเรียน ช่วงเวลา ช่องลงนาม วันเวลาที่ออกรายงาน และไม่มีเมนูหรือปุ่มในกระดาษ |
| 8 | การเงิน + ผู้อำนวยการ | **เอกสารแจ้งยอดเรียกเก็บเงิน** เลือกชั้น | 1 หน้าต่อนักเรียน 1 คน เฉพาะผู้ที่มียอดค้าง ถ้อยคำสุภาพ ผู้อำนวยการตรวจถ้อยคำก่อนใช้ครั้งแรก (D-21) |
| 9 | ผู้ดูแลระบบ | **สำรองและกู้คืนข้อมูล → สำรองข้อมูลตอนนี้** | ไฟล์ใหม่แสดงในรายการ และอยู่ในโฟลเดอร์สำรองใน Google Drive ของเจ้าของระบบ |
| 10 | ผู้ดูแลระบบ | หลังสำรอง ให้การเงินรับเงิน 1 ใบ แล้วผู้ดูแลระบบกด **กู้คืน…** ไฟล์นั้น | ก่อนกู้คืนแสดงจำนวนรายการที่จะหายไป ต้องพิมพ์ "กู้คืนข้อมูล" หลังกู้คืน ทุกคนต้องเข้าสู่ระบบใหม่ รายการรับเงินหลังเวลาสำรองหายไป มีไฟล์ "ก่อนกู้คืน" และประวัติการใช้งานยังครบ |
| 11 | ผู้ดูแลระบบ | กู้คืนจากไฟล์ "ก่อนกู้คืน" ล่าสุด | ข้อมูลกลับมาเหมือนก่อนกู้คืนในข้อ 10 |
| 12 | ผู้ดูแลระบบ | วันถัดไปเปิดหน้า **สำรองและกู้คืนข้อมูล** | มีไฟล์ "อัตโนมัติ" ของเมื่อวาน และ "ผลสำรองอัตโนมัติล่าสุด" = สำเร็จ |
| 13 | ผู้ดูแลระบบ | ลองเรียกข้อมูลการเงิน เช่น เปิดลิงก์ Dashboard | ไม่มีเมนู และ Server ปฏิเสธ (ผู้ดูแลระบบไม่เห็นข้อมูลการเงิน) |

## ข้อห้ามหลังติดตั้ง

| ห้าม | เหตุผล |
|---|---|
| แชร์ไฟล์ Google Sheets หรือโปรเจกต์ Apps Script ให้ผู้อื่นแก้ไข | ผู้ใช้ทุกคนต้องเข้าผ่านเว็บแอปเท่านั้น ระบบจึงควบคุมสิทธิ์และบันทึกประวัติได้ |
| เลือก Execute as = User accessing the web app | ต้องแชร์ไฟล์ให้ทุกคน ซึ่งทำให้แก้ข้อมูลข้ามระบบได้ |
| ส่งลิงก์ที่ลงท้ายด้วย `/dev` ให้ผู้ใช้ | ลิงก์ `/dev` ใช้ทดสอบได้เฉพาะเจ้าของ ผู้ใช้ต้องใช้ลิงก์ `/exec` |
| เปลี่ยนชื่อชีตหรือชื่อหัวคอลัมน์ จัดเรียง (Sort) หรือลบแถวในชีต | โค้ดอ้างอิงตามชื่อ และข้อมูลการเงินต้องไม่ถูกลบ |
| แก้ข้อมูลในชีตด้วยมือ | ข้ามการตรวจสิทธิ์และไม่มีประวัติ (การแก้ AuditLogs จะถูกตรวจพบ) |
| แก้หรือลบค่าใน Script Properties | ระบบจะเปิดฐานข้อมูลหรือตรวจรหัสผ่านไม่ได้ |
| แชร์โฟลเดอร์หรือไฟล์สำรองข้อมูล | ไฟล์สำรองมีข้อมูลนักเรียน ข้อมูลการเงิน และค่าแฮชรหัสผ่าน |
| แก้ไขไฟล์สำรองข้อมูล | ระบบตรวจไฟล์ก่อนกู้คืน ไฟล์ที่ถูกแก้อาจกู้คืนไม่ได้ |
| ลบทริกเกอร์ `dailyBackup` ใน Apps Script | การสำรองอัตโนมัติจะหยุด ถ้าจะปิด ให้ปิดจากหน้าเว็บ (สำรองและกู้คืนข้อมูล → ตั้งเวลาสำรองอัตโนมัติ) |

| ขอปิดเล่มไม่ได้ "มีคำขอยกเลิกเลขที่ที่รออนุมัติ" | ให้ผู้อำนวยการพิจารณาคำขอยกเลิกเลขที่ในเล่มนั้นก่อน |

## ทางเลือก: เข้าสู่ระบบด้วยบัญชี Google ของโรงเรียน

ใช้ได้เมื่อเจ้าของระบบและผู้ใช้ทุกคนมีบัญชีใน Google Workspace โดเมนเดียวกัน (ดูเหตุผลใน ARCHITECTURE.md หัวข้อ 3)

1. ผู้ดูแลระบบกรอก **อีเมล** ของผู้ใช้ทุกคนให้ตรงกับบัญชี Google ของโรงเรียน
2. Apps Script → ⚙️ การตั้งค่าโปรเจกต์ → Script Properties → แก้ `AUTH_MODE` เป็น `GOOGLE`
3. Deploy → Manage deployments → ✏️ → Who has access = **Anyone within (ชื่อโดเมนโรงเรียน)** → Version: New version → Deploy

หลังเปลี่ยน ผู้ใช้กดปุ่ม "เข้าสู่ระบบด้วยบัญชี Google ของโรงเรียน" และไม่ต้องมีรหัสผ่านของระบบ

## สำหรับผู้พัฒนา

### โครงสร้างโค้ด

- ซอร์สโค้ดแยกไฟล์อยู่ใน `src/` แก้ไขที่นี่เท่านั้น
- `dist/Code.gs` สร้างจาก `src/` อัตโนมัติ รวมหน้าเว็บ HTML ไว้ในไฟล์ด้วย ห้ามแก้โดยตรง

```bash
npm run build
```

### ชุดทดสอบ

ต้องมี Node.js 20 ขึ้นไป ไม่ต้องติดตั้งแพ็กเกจเพิ่ม

```bash
npm test
```

ทดสอบหน้าเว็บจริงใน Chromium (ต้องมี Playwright) และบันทึกภาพหน้าจอไว้ที่ `docs/screenshots/`:

```bash
npm run test:e2e
```

- `npm test` รันโค้ดจริงใน `src/` กับ Google Sheets จำลอง (`tests/harness.js`) ครอบคลุมสิทธิ์ทุกคำสั่งกับทุกบทบาท
- `npm run test:e2e` ใช้หน้าเว็บที่ `doGet()` สร้างจริง ต่อกับ Server จำลอง แล้วกดใช้งานจริงทั้งบนคอมพิวเตอร์และมือถือ

### ทางเลือก: ติดตั้งแบบแยกไฟล์หรือด้วย clasp

**แยกไฟล์:**
1. สร้างไฟล์ Script ตามชื่อไฟล์ `.js` ใน `src/`
2. สร้างไฟล์ HTML ตามชื่อไฟล์ `.html` ใน `src/` (เมนู + → HTML)
3. วางเนื้อหาทีละไฟล์

**clasp:**

1. ติดตั้งและเข้าสู่ระบบ

   ```bash
   npm install -g @google/clasp
   ```

   ```bash
   clasp login
   ```

2. คัดลอก `.clasp.json.example` เป็น `.clasp.json` แล้วใส่ Script ID
3. อัปโหลดทั้งโฟลเดอร์ `src/`

   ```bash
   clasp push
   ```
