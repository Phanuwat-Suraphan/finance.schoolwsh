# แผนทดสอบและผลการทดสอบ

ระบบบริหารจัดเก็บเงินบำรุงการศึกษา โรงเรียนวัดเสาหิน จังหวัดเชียงใหม่

| รายการ | รายละเอียด |
|---|---|
| เวอร์ชัน | 1.0.1 (ระยะที่ 8: ทดสอบระบบทั้งหมด) |
| วันที่ | 22 พฤศจิกายน 2569 |
| ผลทดสอบอัตโนมัติ | ผ่านทั้งหมด: ชุดทดสอบ Server 213 กรณี และทดสอบในเบราว์เซอร์จริง 100 รายการ (คอมพิวเตอร์และ iPhone) |
| ที่ยังต้องทำโดยโรงเรียน | ตรวจความพร้อมบน Google จริง (หัวข้อ 4), UAT (หัวข้อ 5), ทดสอบการบันทึกพร้อมกันจาก 2 เครื่อง (หัวข้อ 6) |

> ชุดทดสอบอัตโนมัติรันบน **ตัวจำลอง** ของ Google Sheets และ Apps Script (`tests/harness.js`) ซึ่งตั้งใจให้เข้มงวดกว่าของจริง
> แต่ยังต้องยืนยันบน Google จริงด้วยหัวข้อ 4–6 ก่อนใช้งานจริง ตาม [GO_LIVE.md](GO_LIVE.md)

## 4. ตรวจความพร้อมบน Google จริง (เจ้าของระบบ ทำทุกครั้งที่ติดตั้งหรืออัปเดต)

1. เปิด Google Sheets ของระบบ → เมนู **ระบบเงินบำรุงการศึกษา → 4) ตรวจความพร้อมของระบบบน Google**
2. ต้องขึ้น **"พร้อมใช้งาน: ผ่านทุกข้อ"** และ ✓ ครบ 11 ข้อ:
   เขตเวลา, ชีตครบ, ค่าระบบ, LockService, CacheService, SHA-256, การเก็บข้อความ (เลข 0 นำหน้า วันที่ ภาษาไทย สูตร), การคัดลอกชีต, Google ไดรฟ์, ตัวตั้งเวลาสำรองข้อมูล, ลูกโซ่ประวัติ
3. ข้อนี้ใช้ไฟล์ชั่วคราวแล้วย้ายไปถังขยะ ไม่แก้ข้อมูลจริง
4. ถ้ามีข้อ ✗ ให้แก้ตามข้อความ แล้วตรวจใหม่

## 6. ทดสอบการบันทึกพร้อมกันบน Apps Script จริง (2 เครื่อง)

เตรียม: ในชุดทดสอบ สร้างผู้ใช้เจ้าหน้าที่การเงิน 2 บัญชี (`finance1`, `finance2`) เปิดคนละเครื่อง (หรือคอมพิวเตอร์กับมือถือ)
นับ 1–2–3 แล้วกดปุ่มบันทึกพร้อมกัน

| # | กรณี | ผลที่ต้องได้ |
|---|---|---|
| C1 | ทั้งสองเครื่องรับเงินคนละคน ด้วย**เลขที่ใบเสร็จเดียวกัน** | เครื่องหนึ่งบันทึกสำเร็จ อีกเครื่องขึ้น "เลขที่ใบเสร็จ … ถูกบันทึกแล้ว" ไม่มีเลขที่ซ้ำ |
| C2 | ทั้งสองเครื่องรับเงิน**นักเรียนคนเดียวกันเต็มยอดค้าง** | เครื่องหนึ่งสำเร็จ อีกเครื่องขึ้นว่าเกินยอดคงเหลือ ไม่มีการรับเงินเกินยอด |
| C3 | กดบันทึกรับเงินซ้ำหลายครั้งเร็ว ๆ หรือปิด Wi-Fi ระหว่างบันทึกแล้วเปิดใหม่และกดซ้ำ | ได้ใบเสร็จในระบบ 1 รายการเท่านั้น |
| C4 | ผู้อำนวยการกดอนุมัติลดหย่อน พร้อมกับการเงินรับเงินจากนักเรียนคนนั้นเต็มยอด | ถ้ายอดเปลี่ยนไปแล้ว การอนุมัติแจ้งว่ายอดเปลี่ยน ไม่มียอดติดลบ |
| C5 | ผู้ดูแลระบบกด "สำรองข้อมูลตอนนี้" แล้วการเงินบันทึกรับเงินทันที | การบันทึกรอจนสำรองเสร็จ หรือแจ้ง "มีผู้ใช้อื่นกำลังบันทึก" แล้วกดใหม่ได้ |

หลังทดสอบ: เปิดหน้า **ตรวจความถูกต้องของข้อมูล → ตรวจตอนนี้** ต้องผ่านครบ 8 ข้อ

## 7. ทดสอบความปลอดภัย (ผู้ดูแลระบบ ในชุดทดสอบ)

| # | ทดสอบ | ผลที่ต้องได้ |
|---|---|---|
| S1 | ใส่รหัสผ่านผิด 5 ครั้ง | บัญชีถูกล็อก 15 นาที แม้ใส่รหัสถูก และมีประวัติ |
| S2 | ส่งลิงก์ให้คนที่ไม่มีบัญชีของระบบเปิด | เห็นเฉพาะหน้าเข้าสู่ระบบ ไม่เห็นข้อมูลใด ๆ |
| S3 | เข้าสู่ระบบเป็นผู้อำนวยการ กด F12 → Console พิมพ์ `App.api('payments.create', {}).catch(function (e) { console.log(e.code); })` | ได้ `FORBIDDEN` (Server ปฏิเสธ แม้เรียกตรง) |
| S4 | เพิ่มนักเรียนชื่อ `<b>ทดสอบ</b><script>alert(1)</script>` | แสดงเป็นตัวอักษรธรรมดา ไม่มีหน้าต่างเด้ง |
| S5 | นำเข้าไฟล์ที่มีชื่อ `=HYPERLINK("http://example.com","คลิก")` | ในชีตเป็นข้อความ ไม่ใช่สูตรหรือลิงก์ |
| S6 | เจ้าของระบบแก้จำนวนเงิน 1 ช่องในชีต `Payments` โดยตรง แล้วเปิดหน้าตรวจความถูกต้อง | ตรวจพบในข้อ "การรับเงินตรงกับการตัดชำระ" (แก้กลับให้ตรงเดิมหลังทดสอบ) |
| S7 | ออกจากระบบ แล้วกดปุ่มย้อนกลับของเบราว์เซอร์ | กลับไปหน้าเข้าสู่ระบบ ไม่เห็นข้อมูลเดิม |
| S8 | เข้าสู่ระบบแล้วไม่ใช้งาน 30 นาที (ไม่ได้เลือก "อยู่ในระบบต่อ") | ต้องเข้าสู่ระบบใหม่ |
| S9 | เข้าสู่ระบบเป็นผู้ดูแลระบบ | ไม่มีเมนูการเงิน เปิดลิงก์ Dashboard ไม่ได้ |
| S10 | เปิด Apps Script → การดำเนินการ (Executions) ดู Log | ไม่มีรหัสผ่านหรือ token |

## 8. ทดสอบเวลาตอบสนองบน Google จริง

ทำในชุดทดสอบที่มีข้อมูลขนาดใกล้เคียงโรงเรียนจริง แล้วจดเวลา (ใช้เป็นข้อมูลอ้างอิง ไม่ใช่เกณฑ์ผ่าน/ไม่ผ่าน)

| การทำงาน | เวลาที่คาด (วินาที) | เวลาจริง |
|---|---|---|
| เข้าสู่ระบบ | 2–5 | |
| เปิดหน้ารับชำระเงินของนักเรียน 1 คน | 2–4 | |
| บันทึกรับเงิน | 3–6 | |
| เปิด Dashboard / ยอดค้าง / รายงาน | 3–8 | |
| สำรองข้อมูลตอนนี้ | 20–90 | |
| ตรวจความถูกต้องของข้อมูล | 5–30 | |

> บน Apps Script แต่ละคำขอใช้เวลา 1–3 วินาทีเป็นพื้นฐาน ระบบอ่านชีตไม่เกิน 20 ครั้งต่อคำขอ (ตรวจใน `volume.test`)
